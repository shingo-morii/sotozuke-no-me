# 新しいゲームを取り込む

目の見えない人が遊べるように、ゲームの画面の作りを調べて設定のファイルにする。調べるときは `ingest` の道具がキーとマウスを送る。遊ぶときの本体がゲームへ送るのは、利用者が設定の対応表（`input`）のキーを押した直後だけで、1回押して1つのマウスの動きだけ。対応表が空なら何も送らない。

## 守ること

- 見てよいのは画面と音だけ。インストール先、セーブ、メモリ、台本を開かない。ゲームの名前を Web で調べない
- 前からあるセーブは読まず、上書きしない。試験のセーブは空の枠に置く
- 設定を変えたら、元の値を記録に書き、最後に戻す。文字の速さをいちばん速くした場合だけは残して、設定のファイルと利用者への案内に書く
- 人に聞かない。迷ったら決めて記録に書く
- 権利の無いゲームの見本の画面と設定はコミットしない。`.local\` に置く

## 道具

`python -m ingest.gamectl --process <exe> --work <作業フォルダ> <命令>` で操作する。命令は `shot 名前`、`key enter`、`keys down enter`、`hold shift 5`、`burst 名前 回数 間隔`、`mark 目標の名前`、`size`。マウスは `click x y`（右は `click x y right`）、`move x y`、`wheel x y 刻み`（上が正）。座標は窓の中の座標で、撮った画面の画素と同じ。動作は全部 `actions.jsonl` に時刻つきで残るので、自分で数えなくてよい。マウスの道具を自分で書かない。

そのほかの道具。

- `python -m ingest.locate 画像...`：Claude に本文の帯の位置を聞き、字の形で詰める
- `python -m ingest.template 画像 左 上 右 下 出力`：画面の種類の見本を切り出す
- `python -m ingest.check_map 設定 撮りためたフォルダ`：設定を全部の画面に当てて、当たりと外れを数える
- `python -m ingest.voice_table ...`：文ごとに音の大きさと札の有無を表にする
- `python -m ingest.action_time 記録`：探索の時間と、キー、マウスの押し、撮影の回数を出す

## 目標

順に届き、届くたびに `mark` を打つ。タイトル、はじめから、本文、名前の札、声の有無、次へ、選択肢、場面の切り替わり、場面の説明、セーブ、ロード、タイトルからロード。行き先の地図など、ゲームにあるものは足す。ゲームに無い目標は「無い」と記録する。

13番目は「キーだけで最後まで遊ぶ」。作った設定で本体（`python -m sotozuke --game 設定`）を起動し、利用者の代わりにキーだけを送って、物語の始めから最後まで通す。マウスは使わない。読み落とし、二重の読み、失敗の音を数える。届いたら `mark キーだけで最後まで遊ぶ` を打つ。

物語を進めるだけの区間は、前後に `mark 進行開始` と `mark 進行終了` を打つ。

## 調べる順

1. **NVDA のモードと、ゲームが前に出ているかを最初に確かめる。**最初の撮影で、ゲームの窓が前に出ているかを見る（同じ PC を人が使っていることがある）。字のキーを1つ `gamectl` で送り、別のプロセスの `GetAsyncKeyState` の見回りで見えるかを見る。見えなければ、NVDA がゲームの窓をブラウズモードで開いている。NVDA キー＋Space でフォーカスモードにしてから続ける。ブラウズモードでは字や矢印のキーがゲームにも本体にも届かない。そのあと、入力が届くかを試す。起動したら、短く押して動くかを見る。読み込みの最中の入力は捨てられることがあるので、動かなければ少し待つ。キーで動かなければ、マウスの押しを試す
2. **最初の文の画面で、Enter と本文の上の押し（`click`）の両方を試す。**キーで文が進まないゲームがある。そのあと、画面の種類ごと（タイトル、選択肢、メニュー、セーブ、ロード、確認の窓）に、キーで動くかマウスが要るかを試し、設定の `input` の `keys` に書く。**本体に見えるキーも、ここで確かめる。**ゲームの窓を前に出したまま、別のプロセスで `GetAsyncKeyState` の見回り（キーの番号は `sotozuke.inputs` の `VK`）を回し、`gamectl key 名前` で1つずつ送って、見えたキーを書き出す。短い確かめで分かる。送ったキーでゲームが動くこともあるので、動いても戻せる画面で送る。対応表のキーは、見えたキーの中から選ぶ。候補のキーは、その画面で選べる物（枠など）に乗せた状態でも押して確かめる。乗せると動くキーがある。F11 で全画面になるゲーム、字のキーで日本語入力の変換の窓が出るゲームがある
3. **キーで動かない画面は、マウスの対応を作る。**`input` の `actions` に、キーと動き（`move`、`click`、`wheel`）の対応を書く。行を選ぶ画面（選択肢、セーブやロードの枠）は `rows` に行の箱を書く（選択肢は `"choice"`）。上下のキーでマウスを次の行に乗せ、決めるキーで押す。対応に使うキーは、その画面でゲームが何もしないことを、押して画面が変わらないことで確かめる。本体はキーをゲームに届けたまま送るので、ゲームが動くキーを使うと2回動く。キーが効くのに、選ばれている所が画面に出ないゲームがある（見えない選択）。Enter や Space を押すと、見えない選択を押してしまう。上下と Enter と Space は対応表に使わない。対応表のキーは、ゲームが何もしないキーだけにする。文を進める動きには `"as": "advance"` を書く。対応表のキーは、本体を起動して押したとき、本体の記録に `key` が出るかで確かめる。出ないキーは使わない（送ったキーが本体に見えないことがある）。行の箱（`rows`）は、本体が乗せたときに読み手で読むので、枠やボタンの字が全部入る大きさにする。書き方と使えるキーは `games/README.md` の「キーで動かないゲームの書き方」と「対応表に使えるキー」
4. **操作の案内を先に読む。**本文の画面で案内を出せるキーを探す。案内があれば、メニューを手で探す前に全部のキーが分かる
5. **文字の履歴を探す。**名前と文が並んで読めるなら、字の答え合わせに使える
6. **早送りとオートを探す。**1回ずつ進める前に試す。選択肢で止まるかも見る
7. **画面の種類を分ける。**下や上の案内の字の形を見本にする。色では分けない（服や背景に引っかかる）。見本は `check_map` で全部の画面に当て、当たりの最小とほかの最大の間に余裕があることを確かめる。画素で比べる見本（`match` が `pixel`）は、ほかの画面にも高い点が出る。見本ごとに「自分の画面の最小」と「ほかの画面の最大」を数えてから閾値を決める。ほかの画面にも当たる見本と重なる画面は、`screens` の先に並べる。撮りためる道具は、暗い画面の短い文を選択肢と取り違えることがある。撮りためには害が無いが、見本の確かめで数える。決まった字や枠の無い画面の見分け方、見分けが揺れるときの枚数など、使える項目は `games/README.md` の「すべての項目」で探す
8. **セーブ、ロード、タイトルからのロードを、物語を進める前に済ませる**
9. **早送りで進めて、選択肢とほかの種類の画面に出会う。**止まるたびに種類を足す。もう読んだ文の色が変わるかを早く見る
10. **声を調べる。**背景の音楽が鳴り続けるなら、ゲームの設定で音楽を消してから測る。設定の画面が無く音楽を変えられないゲームは、変えずに測る。消すのは BGM だけ。効果音は消さない。声が効果音の音量で鳴るゲームがある。音で測るときは、1文の待ちを声より長くする。短いと前の文の声が次の文に混ざる。`voice_table` で1文ごとに表を作り、数えてから結論を書く。効果音があるので音の大きさだけで決めない。見分け方は、札で見る `tag`、音で見る `audio`、全部読む `all` から選ぶ。札と声の関係はゲームごとに違うので決めつけない
11. **場面の切り替わりを調べる。**`burst` で連続で撮り、全面が黒か白を通るかを見る。通らないなら、文が出るたびに前の文の絵と比べる見方（`scene.text_diff`）を使う。同じ場面の文どうしの差と、場面が変わった文の差を測り、間の値を書く
12. **設定のファイルを書き、`check_map` と、本体の通しで確かめる**
13. **キーだけで最後まで遊ぶ。**目標の13番目。利用者の代わりの道具は、本体の記録の `read_start` と `read_done` を数えて、読み終わるのを待ってから次のキーを送る。本体を止めるときは、Python のプロセスの番号で止める

## 見分けの決まり

- 画面の種類を先に決め、文の画面でだけ札を見る。札の線は選択肢や履歴の画面にも残る
- 選択肢の画面には前の文が残っている。見本の種類で文の見張りを止める
- 選ばれている行は、行の明るさの比べで決める。閾値で決めると明るい背景で外れる
- 選ばれている行は、明るくなるとは限らない。乗せると暗くなるゲームがある。行ごとの明るさを、乗せたときと外したときで測る。暗くなるなら `choice.selected` を `dark` にし、乗せた行とほかの行の差より小さく、外したときの行どうしの差より大きい値を `dark_margin` に書く
- 項目の数は画面から数えず、読み手が読んだ項目の数を使う
- 白の数ではなく、字の縁の形で数える。明るい背景でも崩れない
- 文字の色が途中で変わるゲームがある（設定の画面のあとなど）。字の明るさの閾値（`glyph`）は、色の違う文で数えてから決める
- 本体の履歴の読み方（`backlog`）は、明るい行がある履歴に合わせた作り。明るい行の無い履歴は `card` の種類で読む
- Esc で閉じない画面がある。閉じたことを画面で確かめてから次を押す
- 文字が一度に出るか、1字ずつ出るかを確かめて `text.typed` に書く。一度に出るなら背景が動いても見落としにくい見方になる
- 声の無いゲームで名前の札があるなら、`tag.read_name` で札の字も読む（`tag.box` が要る）。「名前。本文」と読まれる
- 文の終わりの「次へ」の印を読み手が字として返すなら、その字を `text.end_marks` に書く。終わりの1字だけ外す。物語の文の終わりに来る字（。、！、？、英字の .）は書かない
- マウスの左ボタンで動く画面を利用者が押すこともあるなら、`keys.cursor` に `lbutton` を書く。押したあとの画面の変化を読む
- 名前の札は、字の形より、札の縁の線で見分ける方が外れにくいことがある。線だけでなく名前の字の形でも見られる。明るい背景で線が消えないかを確かめ、当たりの最小とほかの最大の間に余裕があるほうを選ぶ
- 音で見るゲームは、`voice_table` の表から背景の音楽と声の針の値を見て、間の値を `audio_threshold` に書く。効果音と前の文の声の残りが混ざるので、札で見られるなら札を選ぶ
- 確かめた画面の大きさを `size` に書く。別の大きさでは読まないので、窓の大きさが変わるゲームは大きさごとに設定を作る
- 札が人の名前でなく場所の名前のことがある。場所の札でも札の見分けが当たるか、`tag.read_name` で場所の名前が読まれるかを、本体の記録で確かめる（11-07、場所の札を読まなかった所があった。原因は分かっていない）
- 歩く画面は、1周を12枚ほど撮って1枚にまとめると、どこへ行くかを1回で決められる。回る速さは、押し続けて撮った画面で景色が戻るまでの秒数から出せる。街灯や植え込みに引っかかることがある
- 本文の帯は `ingest.locate` に長い文の画面を混ぜて渡す。短い文だけだと帯が狭く出る。いちばん長い文が入るか、帯を確かめて、足りなければ設定で広げる

## 残すもの

- `games/<ゲーム>.json`（書き方は `games/README.md`。設定の全部の項目の名前、意味、既定は「すべての項目」にある。マウスの対応（`input`）、行の読み上げ、暗い選択の行、暗転を通らない場面、札の名前、終わりの印、`lbutton` は、その中の「キーで動かないゲームの書き方」に、仮の値の例と項目ごとの説明がある。対応表のキーの選び方は「対応表に使えるキー」。本体のコードと `docs/G1b_設計.md` は読まなくてよい）：大きさ、窓のプロセスの名前、字の形、本文の帯、札、声の見分け方、場面の範囲、画面の種類、選択肢の行、キー、画面ごとの入力の対応（`input`）
- 見本の画面：設定から相対のパスで指す
- 探索の記録：`action_time` の出力、つまずいた所、次のゲームで早くできること

## 経験

1本取り込むごとに、ここに足す。いつ、どのゲームから分かったかを書く。ゲームの座標やキーは書かず、調べ方だけを書く。

- 11/2 基準のゲームから：キーの押す時間が短いと取りこぼす。0.1秒以上押す。`gamectl` の既定は0.12秒
- 11/2 基準のゲームから：案内を先に読まずにメニューを手で探して遠回りした。案内のキーを最初に探す
- 11/2 基準のゲームから：長い自動の処理は、失敗したらすぐ止まるように書く。手順の中に混ぜて放っておかない
- 11/2 基準のゲームから：結論を数える前に書いて間違えた。表を機械で作ってから書く
- 11/2 基準のゲームから：動く場面と明るい場面を見本に入れないと、見分けが本番で崩れる。止まった画面だけで確かめない
- 11/2 基準のゲームから：読み込みの画面は見本を `loading` の種類で足す。場面と間違えて説明を作ってしまう
- 11/2 基準のゲームから：本文の帯に飾りが入ると、字の形の大半が飾りになり、別の文でも同じ文に見える。帯を飾りの内側に狭める。別の文どうしの重なりを数えて確かめる
- 11/2 基準のゲームから：名前が「???」のように短いと字の形では見落とす。線と字の形の両方を設定する（kind either）
- 11/2 基準のゲームから：確認の窓は何種類も出る。字でなく窓の枠の絵を見本にする（match pixel）
- 11/2 基準のゲームから：地図の選択中の印はゲームごとに違う。字でなく絵で示すなら、画面の種類の `prompt` と `prompt_move` に見方を書く
- 11/3 基準のゲームから：地図は項目を動かして確かめてから決定する。決定のあと戻れないことがある
- 11/3 基準のゲームから：背景の模様が字の形に入ると、別の文の重なりが0.7を超える。長い通しで短い文の読み落としを数える
- 11/3 基準のゲームから：取り込みの最後に、なるべく長い区間を通しで走らせる。短い試験で見えない問題が出る
- 11/4 基準のゲームから：確認の窓は「いいえ」のあと開き直すことがある。続けて押す Enter が「はい」になる。窓が閉じたのを確かめてから次を押す
- 11/4 基準のゲームから：歩く画面の相手は、場所を知っていても向きを合わせるのが難しい。1周を撮って1枚にまとめると、画面を見る回数が減る
- 11/4 基準のゲームから：同じ道を2週通すと、読み手の誤りがいつも同じ所で出るか、たまたまかが分かる
- 11/4 基準のゲームから：歩く画面は、地図で選んだ人の見た目を覚えさせ、止まるたびに「何度右か、どれくらい近いか」を言わせると、6か所のうち4か所は画面を見ずに会えた。設定には回る速さ（押し続けて1周の秒数から）と画角を書く
- 11/4 基準のゲームから：回る速さは、同じ合計の長さを短く何度も押した場合と長く押した場合で、向きが同じになるかで確かめる。画角は、カメラが人の周りを回るゲームでは絵のずれから測れない
- 11/4 基準のゲームから：歩く画面から開く地図は、案内の字がメニューと同じことがある。地図にだけ出る字（移動先を選択してください）を見本にする
- 11/4 基準のゲームから：選択肢のガイドのおすすめは、カーソルの印の形（ハート）で示されることがある
- 11/6 1本目のゲームから：キーが届かないゲームがある。`gamectl` の `click`、`move`、`wheel` を使う。前は道具を自分で書いて5分ほどかかった
- 11/6 1本目のゲームから：最初の文の画面で、Enter と本文の上の押しの両方を試す
- 11/6 1本目のゲームから：もう読んだ文の色が変わるかを早く見る。1回目の画面だけで字の基準を決めると、2回目に崩れた
- 11/6 1本目のゲームから：黒も白も通らない場面の切り替わりがある。文が出るたびに前の絵と比べる（`scene.text_diff`）
- 11/6 1本目のゲームから：背景の音楽が鳴り続けるゲームは、BGM を消してから声を測る。消すのは BGM だけ。効果音は消さない。声が効果音の音量で鳴るゲームがある
- 11/6 1本目のゲームから：効果音まで消して測り、声を見落とした
- 11/6 1本目のゲームから：`gamectl` で送ったキーのうち、本体に見えないものがあった。対応表のキーは、本体の記録に `key` が出るかで確かめてから使う
- 11/6 1本目のゲームから：遊ぶ間に Windows の通知が本文の上に重なると、本体が新しい文と見て読み始める。通しの前に通知を切る
- 11/6 1本目のゲームの取り込み直しから：本体に見えるキーを、探索の最初に確かめる。`gamectl` で送り、`GetAsyncKeyState` で見る短い確かめで分かる。後で確かめたので、対応表を全部作り直した（約15分）

- 11/6 1本目のゲームの取り込み直しから：画素で比べる見本は、ほかの画面にも高い点が出る。見本ごとに「自分の画面の最小」と「ほかの画面の最大」を数えてから閾値を決める。重なる画面は先に並べる

- 11/6 1本目のゲームの取り込み直しから：文字の色が途中で変わるゲームがある（設定の画面のあとなど）。字の明るさの閾値は、色の違う文で数えてから決める
- 11/6 1本目のゲームの取り込み直しから：本体の履歴の読み方は、明るい行がある履歴に合わせた作り。明るい行の無い履歴は `card` で読む
- 11/6 1本目のゲームの取り込み直しから：Esc で閉じない画面がある。閉じたことを画面で確かめてから次を押す
- 11/6 1本目のゲームの取り込み直しから：撮りためる道具で、暗い画面の短い文を選択肢と取り違えることがある。撮りためには害が無いが、見本の確かめで数える
- 11/7 2本目と3本目のゲームから：NVDA のブラウズモードでは、字や矢印のキーがゲームにも本体にも届かなかった。Enter、Space、Esc、F キー、Delete、Backspace は素通りした。調べる順の最初に、字のキーを1つ送って `GetAsyncKeyState` で見えるかを見る。見えなければ NVDA キー＋Space でフォーカスモードにする
- 11/7 2本目と3本目のゲームから：対応表の候補のキーは、その画面で選べる物（枠など）に乗せた状態でも確かめる。乗せない状態で何も起きなくても、乗せると動くキーがある（消去の確認が出た）
- 11/7 2本目と3本目のゲームから：F11 で全画面になるゲームがある。字のキーで日本語入力の変換の窓が出ることがある
- 11/7 2本目と3本目のゲームから：同じ PC を人が使っていることがある。最初の撮影で、ゲームが前に出ているかを確かめる（スタートの検索にキーが入った）
- 11/7 2本目と3本目のゲームから：画素で比べる見本と字の形の見本を混ぜるときは、画素の見本が当たればすぐその画面に決まることを考える。見本ごとに、自分の画面の最小とほかの画面の最大を数えてから閾値を決める
- 11/7 2本目と3本目のゲームから：名前の札は、字の形より、札の縁の線で見分ける方が外れにくいことがある
- 11/7 2本目と3本目のゲームから：利用者の代わりの道具は、本体の記録の読み手の始まりと終わり（`read_start` と `read_done`）を数えて待つ。待たずに次のキーを送ると、読みが途中で切れる
- 11/7 2本目と3本目のゲームから：本体を止めるときは、Python のプロセスの番号で止める。包みのシェルだけ止まって本体が残ることがある
- 11/7 2本目と3本目のゲームから：歩く画面は、1周を12枚ほど撮って1枚にまとめると、どこへ行くかを1回で決められる。回る速さは、押し続けて撮った画面で景色が戻るまでの秒数から出せる。街灯や植え込みに引っかかることがある
- 11/7 2本目と3本目のゲームから：設定の画面が無いゲームがある。文字の速さや音楽を変えられないときは、変えずに測る（声は、音楽より十分大きければ消さずに見分けられた）
- 11/7 2本目と3本目のゲームから：設定の書き方が README に足りず、本体の誤りの文や型の情報から項目を探して時間を使った。設定の全部の項目は `games/README.md` の「すべての項目」にある。知らない項目を書くと、読み込みの誤りの文に書ける項目が並ぶ
