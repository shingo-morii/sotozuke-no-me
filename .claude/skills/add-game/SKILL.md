# 新しいゲームを取り込む

目の見えない人が遊べるように、ゲームの画面の作りを調べて設定のファイルにする。遊ぶときの本体はゲームにキーを送らないが、この調べのときだけ `ingest` の道具がキーを送る。

## 守ること

- 見てよいのは画面と音だけ。インストール先、セーブ、メモリ、台本を開かない。ゲームの名前を Web で調べない
- 前からあるセーブは読まず、上書きしない。試験のセーブは空の枠に置く
- 設定を変えたら、元の値を記録に書き、最後に戻す。文字の速さをいちばん速くした場合だけは残して、設定のファイルと利用者への案内に書く
- 人に聞かない。迷ったら決めて記録に書く
- 権利の無いゲームの見本の画面と設定はコミットしない。`.local\` に置く

## 道具

`python -m ingest.gamectl --process <exe> --work <作業フォルダ> <命令>` で操作する。命令は `shot 名前`、`key enter`、`keys down enter`、`hold shift 5`、`burst 名前 回数 間隔`、`mark 目標の名前`、`size`。動作は全部 `actions.jsonl` に時刻つきで残るので、自分で数えなくてよい。

そのほかの道具。

- `python -m ingest.locate 画像...`：Claude に本文の帯の位置を聞き、字の形で詰める
- `python -m ingest.template 画像 左 上 右 下 出力`：画面の種類の見本を切り出す
- `python -m ingest.check_map 設定 撮りためたフォルダ`：設定を全部の画面に当てて、当たりと外れを数える
- `python -m ingest.voice_table ...`：文ごとに音の大きさと札の有無を表にする
- `python -m ingest.action_time 記録`：探索の時間とキーの回数を出す

## 目標

順に届き、届くたびに `mark` を打つ。タイトル、はじめから、本文、名前の札、声の有無、次へ、選択肢、場面の切り替わり、場面の説明、セーブ、ロード、タイトルからロード。行き先の地図など、ゲームにあるものは足す。ゲームに無い目標は「無い」と記録する。

物語を進めるだけの区間は、前後に `mark 進行開始` と `mark 進行終了` を打つ。

## 調べる順

1. **入力が届くかを最初に試す。**起動したら、短く押して動くかを見る。読み込みの最中の入力は捨てられることがあるので、動かなければ少し待つ
2. **操作の案内を先に読む。**本文の画面で案内を出せるキーを探す。案内があれば、メニューを手で探す前に全部のキーが分かる
3. **文字の履歴を探す。**名前と文が並んで読めるなら、字の答え合わせに使える
4. **早送りとオートを探す。**1回ずつ進める前に試す。選択肢で止まるかも見る
5. **画面の種類を分ける。**下や上の案内の字の形を見本にする。色では分けない（服や背景に引っかかる）。見本は `check_map` で全部の画面に当て、当たりの最小とほかの最大の間に余裕があることを確かめる
6. **セーブ、ロード、タイトルからのロードを、物語を進める前に済ませる**
7. **早送りで進めて、選択肢とほかの種類の画面に出会う。**止まるたびに種類を足す
8. **声を調べる。**`voice_table` で1文ごとに表を作り、数えてから結論を書く。効果音があるので音の大きさだけで決めない。見分け方は、札で見る `tag`、音で見る `audio`、全部読む `all` から選ぶ。札と声の関係はゲームごとに違うので決めつけない
9. **場面の切り替わりを調べる。**`burst` で連続で撮り、全面が黒か白を通るかを見る。通らないなら、場面の見分けが使えないことを記録に書く
10. **設定のファイルを書き、`check_map` と、本体の通しで確かめる**

## 見分けの決まり

- 画面の種類を先に決め、文の画面でだけ札を見る。札の線は選択肢や履歴の画面にも残る
- 選択肢の画面には前の文が残っている。見本の種類で文の見張りを止める
- 選ばれている行は、行の明るさの比べで決める。閾値で決めると明るい背景で外れる
- 項目の数は画面から数えず、読み手が読んだ項目の数を使う
- 白の数ではなく、字の縁の形で数える。明るい背景でも崩れない
- 文字が一度に出るか、1字ずつ出るかを確かめて `text.typed` に書く。一度に出るなら背景が動いても見落としにくい見方になる
- 名前の札は、線だけでなく名前の字の形でも見られる。明るい背景で線が消えないかを確かめ、当たりの最小とほかの最大の間に余裕があるほうを選ぶ
- 確かめた画面の大きさを `size` に書く。別の大きさでは読まないので、窓の大きさが変わるゲームは大きさごとに設定を作る
- 本文の帯は `ingest.locate` に長い文の画面を混ぜて渡す

## 残すもの

- `games/<ゲーム>.json`：大きさ、窓のプロセスの名前、字の形、本文の帯、札、声の見分け方、場面の範囲、画面の種類、選択肢の行、キー
- 見本の画面：設定から相対のパスで指す
- 探索の記録：`action_time` の出力、つまずいた所、次のゲームで早くできること

## 経験

1本取り込むごとに、ここに足す。いつ、どのゲームから分かったかを書く。ゲームの座標やキーは書かず、調べ方だけを書く。

- 11/2 基準のゲームから：キーの押す時間が短いと取りこぼす。0.1秒以上押す。`gamectl` の既定は0.12秒
- 11/2 基準のゲームから：案内を先に読まずにメニューを手で探して遠回りした。案内のキーを最初に探す
- 11/2 基準のゲームから：長い自動の処理は、失敗したらすぐ止まるように書く。手順の中に混ぜて放っておかない
- 11/2 基準のゲームから：結論を数える前に書いて間違えた。表を機械で作ってから書く
- 11/2 基準のゲームから：動く場面と明るい場面を見本に入れないと、見分けが本番で崩れる。止まった画面だけで確かめない
- 11/2 基準のゲームから：読み込みの案内の字は本文の帯に出ることがある。見つけたら `text.ignore` に書く
- 11/2 基準のゲームから：地図の選択中の印はゲームごとに違う。字でなく絵で示すなら、画面の種類の `prompt` と `prompt_move` に見方を書く
