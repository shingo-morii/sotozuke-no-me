# P9 で守井が確かめること

機械では決められないもの。音を聞いて、手で触って決める。

- 声の聞きやすさ。Haruka の速さ（Rate 2 にしてある）
- 文が出てから声までの遅れ。キーを押してから読み始めるまで、中央値が約2秒。声ありの文は読まないので待たない
- 読みが割れた文は、読み始めが約1.5秒遅い。1割強の文で起きる。この間は3秒の音を4.5秒まで待たせている。守井の「3秒」のきまりから変えた点なので、これでよいか
- 場面の説明は長いと約8秒かかり、その間は最初の文を待たせる。説明を短くするか、毎回自動で読むのをやめるか
- 場面の説明を毎回自動で読むのが、うるさくないか
- 説明の質。全盲の人が場面を想像できるか
- 説明の代わりに鳴る合図の音（880Hz、0.12秒）が分かりやすいか。失敗の音（330Hz、0.25秒）と聞き分けられるか
- 彩を使うか。彩は1文に約1秒多くかかる。Haruka は0.05秒以内
- 行き先の地図の説明で、行き先の人物が伝わるか。今は見た目だけで、名前は言わない
- コントローラの実機。読み直しと説明のボタンの位置
- F6、F7、F8 の位置が使いやすいか。ゲームのキーとぶつからないか
- 説明の途中で次へ進むと最初の文が読まれない動き。止めるキー F8 だと文が読まれる。これで困らないか
- 「………」だけの札の文。札があると読まないので、無言の間に気づけるか。札が無い点だけの文は「無言」と読む
- 同じ文が続けて出たときは、キーから約1.6秒たって読み直す。遅れが気にならないか
- 読み手がときどき2秒から3.6秒に遅れる。そのときは短い音が鳴ってから読む
- メニューの読み上げは1項目ごとに約1.3秒かかる。セーブの枠の読み方（日時や曜日まで読む）が長すぎないか
- 地図の読み上げは約2.5秒かかる。動かすたびに読むので遅くないか
- NVDA と同時に使ったときの、声の重なり
- README の「問題の数字」を、出典を確かめて書く

## 11-03 エンディングまでの通しから足したこと

- 地図の決定の1回目のあと、キーボードで戻る方法を探す
- 歩く画面の説明キーで、人と入口が分かるか
- 地図の読み上げが長くないか。選択中が外れたときに困らないか
- 文が読まれないまま止まったときに、読み直しのキーで足りるか

## 11-04 2週の通しから足したこと

- 歩く画面の説明キーで、地図で選んだ人がどこに見えるか分かるか
- 確認の窓で「いいえ」を押したあと、窓が開き直したときに気づけるか
- 選択肢を選んだあと、前の文がもう一度読まれて邪魔にならないか

## 11-04 4周目（歩く画面の道案内）から足したこと

- 歩く画面に入ったとき、操作の案内と「目当ての人は右へ20度、近い」のような声が分かりやすいか
- 矢印を押している間の30度ごとの音と90度ごとの音で、どれだけ回したか分かるか
- 止まるたびに「見えません」「右へ20度、中くらい」と言われるのが、うるさくないか
- 歩いて壁にぶつかったときの低い音に気づけるか

## 11-06 G1b から足したこと

- キーで動かないゲームでは、本体が利用者のキーの直後にマウスを動かして押す。手元のマウスの位置も動く。NVDA を使っていて困らないか
- 声の無いゲームで「名前。本文」と読む形が聞きやすいか
- 基準のゲームの通しで、暗い背景が明けるときに地の文を1つ読み落とした。直すかどうかを決める
- 手で押した文字のキー（n など）が本体に見えるか。試験の道具から送った文字のキーは、1本目のゲームの窓では本体に見えなかった。私の小さな試しの窓では見えた
- セーブやロードの枠、確認の窓のボタンで、乗せるたびに枠の字を読む形が分かりやすいか
- 行を選ぶ画面で、行を読む前の決めるキーに「行を選んでください。」と言う形が分かりやすいか
