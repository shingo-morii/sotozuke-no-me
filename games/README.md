# ゲームごとの設定

`add-game` のスキルが作る JSON をここに置く。権利の確かなゲームの設定だけをコミットする。権利の無いゲームの設定と見本の画面は `.local\` に置く。

主な項目は次のとおり。

- `size`：この設定が対応する画面の大きさ。ほかの大きさでは読まず、声で知らせる
- `voice_rule`：声の見分け方。`tag` は札で見る、`audio` は音で見る、`all` は全部読む
- `text`：本文の帯の位置と、字が止まったと見なす時間
- `tag`：名前の札の見分け方
- `scene`：場面の切り替わりを見る範囲
- `screens`：画面の種類の一覧。案内の字の形を見本と比べる
- `choice`：選択肢の範囲と、項目の数ごとの行の位置
- `keys`：次へ進むキーとカーソルのキー。入力を見るために使う。マウスの左ボタンを見るなら `lbutton` を書く
- `input`：画面ごとの入力の対応。キーで動かない画面で、利用者のキーをマウスの動き（動かす、押す、ホイール）に言い換える。書いていなければ本体は何も送らない
- `tag.read_name`：札のある文で札の字も読む。`choice.selected`：選ばれている行が明るいか暗いか。`scene.text_diff`：暗転を通らない場面の切り替わりを文ごとに見る。`text.end_marks`：文の終わりの「次へ」の印

すべての項目の名前、意味、既定の値は、下の「すべての項目」にある。キーで動かないゲームの書き方の例は「キーで動かないゲームの書き方」にある。

## すべての項目

設定に書ける項目の全部。「既定」の欄が「要る」の項目は、書かないと読み込みで止まる。「既定なし」の項目は、使うときに測って書く（本体に既定の値を置かない）。座標は窓の中の座標で、範囲は `[左, 上, 右, 下]`（右と下は含まない）。知らない項目を書くと、読み込みで止まり、書ける項目の名前を並べて知らせる。

### いちばん上

| 名前 | 意味 | 既定 |
|---|---|---|
| `name` | 設定の名前。記録に出る | 要る |
| `size` | この設定が対応する画面の大きさ `[幅, 高さ]`。ほかの大きさでは読まず、声で知らせる | 要る |
| `process` | ゲームの窓のプロセスの名前（例 `game.exe`）。この窓を撮る | 空 |
| `window_title` | 窓の題。記録のための項目で、本体は使わない | 空 |
| `voice_rule` | 声の見分け方。`tag` は札のある文を声ありと見て読まない、`audio` はゲームの音で見る、`all` は全部読む | `all` |
| `audio_threshold` | `audio` のとき、声と見なす音の針の値。背景の音楽より大きくする | 0.05 |
| `glyph` | 字の形の見分け方（下の表） | 下の表の既定 |
| `text` | 本文の帯（下の表） | 要る |
| `tag` | 名前の札（下の表）。`voice_rule` が `tag` なら要る | 無し |
| `scene` | 場面の切り替わり（下の表）。無ければ場面の説明を自分からは作らない。F7 は押すたびに今の画面を説明する | 無し |
| `screens` | 画面の種類の一覧（下の表） | 空 |
| `choice` | 選択肢（下の表） | 無し |
| `keys` | 入力を見るキー。`advance` は文を進めるキーの一覧、`cursor` はカーソルのキーの一覧。マウスの左ボタンを見るなら `cursor` に `lbutton` を書く | `advance` は `["enter"]`、`cursor` は `["up", "down"]` |
| `walk` | 歩く画面の道案内（下の表） | 無し |
| `input` | 画面ごとの入力の対応（下の表と「キーで動かないゲームの書き方」） | 空。本体は何も送らない |
| `kind_frames` | 画面の種類が変わったと決めるまで、続けて同じ種類に見えた枚数（10枚で1秒）。見分けが入ったり外れたりして同じ種類を何度も言うときに増やす。1以上 | 2 |
| `next_marker` | 文の終わりの「次へ」の印の範囲。記録のための項目で、本体は使わない | 無し |

### `glyph`（字の形）

明るい画素のそばに暗い画素があるものを字と見なす。見本の字の形、本文の帯、札の字、歩く画面の案内の字に使う。

| 名前 | 意味 | 既定 |
|---|---|---|
| `bright` | 字の明るい側の明るさ（0〜255）。これ以上を字の点の候補にする | 190 |
| `dark` | 字の縁の暗い側の明るさ。これ以下が近くにある点だけを字と見る | 110 |
| `radius` | 明るい点から暗い点を探す広さ（画素） | 2 |

### `text`（本文の帯）

| 名前 | 意味 | 既定 |
|---|---|---|
| `band` | 本文の帯の範囲。いちばん長い文が入る大きさにする | 要る |
| `stable_s` | 字がこの秒数止まったら、文が出きったと見なす | 0.3 |
| `new_overlap` | 前の文の字の形との重なりがこれ未満なら、新しい文 | 0.7 |
| `typed` | 文字の出方。`true` は1字ずつ出る、`false` は一度に出る（背景が動いても字の形の揺れに強い見方になる） | `true` |
| `min_pixels` | 帯の字の点がこれより少なければ、字は無い | 40 |
| `ignore` | 帯に出ても読まない字の一覧（読み込みの案内など） | 空 |
| `end_marks` | 文の終わりの「次へ」の印の字。読み手が返した文の終わりの1字だけ外す | 空 |

### `tag`（名前の札）

| 名前 | 意味 | 既定 |
|---|---|---|
| `kind` | 札の見分け方。`hline` は札の横の線、`glyph` は札の字の形、`either` はどちらかが見えれば札 | `hline` |
| `y` | `hline` の線の高さ | 0 |
| `x0`、`x1` | `hline` の線を見る左右の範囲 | 0 |
| `min_cols` | 線が続く列の数がこれ以上なら札がある | 0 |
| `contrast` | 線とその上下の明るさの差がこれ以上なら線 | 25 |
| `box` | 札の字の範囲。`glyph`、`either`、`read_name` で要る | 無し |
| `min_glyphs` | `box` の字の点がこれ以上なら札がある | 0 |
| `read_name` | 札のある文で札の字も読み、「名前。本文」と読む。同じ形の札は覚えて読み直さない。空で返った札は、2回続けて空なら覚える | `false` |

### `scene`（場面の切り替わり）

| 名前 | 意味 | 既定 |
|---|---|---|
| `box` | 場面を見る範囲。本文の帯を外した絵の部分 | 要る |
| `dark_below` | この明るさ未満なら暗転 | 3.0 |
| `bright_above` | この明るさを超えたら白飛び | 250.0 |
| `min_dark_s` | 暗転か白飛びがこの秒数続いたら、場面の切り替わり | 0.3 |
| `settle_frames` | 明けたあと、絵の差が小さい枚数がこれだけ続いたら落ち着いた | 3 |
| `settle_diff` | 落ち着いたと見なす絵の差 | 6.0 |
| `text_diff` | 暗転も白飛びも通らない場面の切り替わり。0より大きければ、文が出るたびに前の文のときの絵と比べ、差がこれ以上なら場面とする | 0（切） |
| `describe` | F7 の説明。`last` は前の場面の説明を言う。`current` は、前の説明の絵と今の絵が違えば、今の画面を説明する（場面の見分けが外れたときの保険） | `last` |

### `screens`（画面の種類）の1つずつ

| 名前 | 意味 | 既定 |
|---|---|---|
| `name` | 画面の名前。`input` の鍵にも使える | 要る |
| `kind` | 種類。`choice`（選択肢）、`map`（行き先の地図）、`walk`（歩く画面）、`menu`（タイトル、設定、セーブ、ロード）、`confirm`（確認の窓）、`card`（字だけを読む札。日付など）、`backlog`（文字の履歴）、`loading`（読み込み。何も読まない） | 要る |
| `box` | 見本と比べる範囲 | 要る |
| `template` | 見本の画像のファイル。設定のファイルからの相対のパス | 要る |
| `threshold` | 見本との点がこれ以上なら当たり（`absent` は未満なら当たり） | 0.7 |
| `match` | 比べ方。`glyph` は字の形、`pixel` は画素（窓の枠など字でないもの）、`absent` は画素で比べて当たらないときにこの画面と見る（決まった字や枠の無い歩く画面を、文の枠が無いことで見分ける。見本は文の枠の一部） | `glyph` |
| `prompt` | この画面に入った直後の、読み手への頼み（地図など） | 空 |
| `prompt_move` | カーソルを動かしたあとの頼み | 空 |
| `read_box` | 歩く画面（`walk`）にだけ書ける。操作の案内の字が出る範囲。字が出たら読む。同じ字が出ている間は読み直さない | 無し |
| `read_min_glyphs` | `read_box` の字の点がこれ以上なら字がある。`read_box` を書くなら要る。字の無い画面と字の出た画面で数えて間に置く | 既定なし |

見本の並び：`pixel` の見本は当たればすぐその画面に決まるので、ほかの画面と重なる画面（確認の窓など）を先に並べる。`glyph` の見本は、当たったうちいちばん点の高いものを選ぶ。`absent` は、ほかの見本が全部外れたときだけ、並びの順に見る。

### `choice`（選択肢）

| 名前 | 意味 | 既定 |
|---|---|---|
| `box` | 全項目が入る範囲。読み手にここを読ませる | 要る |
| `rows_by_count` | 項目の数ごとの行の箱。`{"2": [[...], [...]], "3": [...]}`。知らない数は、書いた数の2つから伸ばして求める。2つ未満で知らない数が出たら、その選択肢は読まない | 空 |
| `selected` | 選ばれている行の見え方。`bright` は明るい行、`dark` は暗い行 | `bright` |
| `dark_margin` | `dark` のとき、ほかの行よりこれだけ暗い行を選ばれている行とする。`dark` なら要る | 既定なし |
| `bright_margin` | `bright` のとき、1位と2位の差がこれ未満なら、はっきり明るい行は無い。選択肢が始まったときなら「選ばれていない」とし、紹介で「選んでいるのは」を言わない | 0（切。いちばん明るい行を選ぶ） |
| `strip_label` | 記録のための項目で、本体は使わない | `true` |

### `walk`（歩く画面の道案内）

| 名前 | 意味 | 既定 |
|---|---|---|
| `move_keys` | 歩くキーの一覧。押しているのに画面が変わらなければ、進めない音を鳴らす | `["w", "a", "s", "d"]` |
| `turn_left`、`turn_right` | 向きを変えるキー | `left`、`right` |
| `turn_deg_per_s` | 向きを変えるキーを押している間に回る速さ（度毎秒）。0 なら角度を言わない | 0 |
| `view_deg` | 画面の横の画角（度）。0 なら「やや右」のような言葉で言う | 0 |
| `tick_deg` | 回している間、この角度ごとに短い音を鳴らす | 30 |
| `bump_diff` | 歩くキーを押しているのに画面の差がこれ未満なら、止まっている | 1.0 |
| `hint` | 初めて歩く画面に入ったときに言う操作の案内 | 空 |
| `target_prompt` | 地図で決めたとき、選ばれている人の見た目を聞く頼み | 空（本体の頼み） |
| `view` | 視点。`behind` は手前に主人公が背中を見せて映る。`first_person` は一人称で主人公は映らない。F7 の説明と、目当ての人を探す頼みの前置きが変わる | `behind` |

### `input`（画面ごとの入力の対応）の1つずつ

鍵は画面の名前か種類（`text` は文の画面）。書き方の例と説明は「キーで動かないゲームの書き方」にある。

| 名前 | 意味 | 既定 |
|---|---|---|
| `keys` | その画面でゲームがキーで動くか。記録のための項目 | `true` |
| `actions` | キーと動きの対応。鍵がキーの名前で、中身は下の表 | 空 |
| `rows` | 行を選ぶ画面の行の箱の一覧。`"choice"` は選択肢の行 | 空 |
| `prev` | 前の行へ乗せるキー | `up` |
| `next` | 次の行へ乗せるキー | `down` |
| `pick` | 今の行を押すキー | `enter` |

`actions` の1つずつ：

| 名前 | 意味 | 既定 |
|---|---|---|
| `do` | `move`（マウスを動かす）、`click`（押す）、`wheel`（ホイールを回す） | 要る |
| `at` | 動きの場所 `[x, y]` | 要る |
| `button` | `click` のボタン。`left` か `right` | `left` |
| `amount` | `wheel` の回す量。上が正。`wheel` では0にできない | 0 |
| `as` | 本体がその押しを何と見るか。`advance`（文を進めた）か `cursor`（カーソルを動かした） | そのキーの元の役目 |

## キーで動かないゲームの書き方

マウスが要るゲーム、選ばれている行が暗いゲーム、場面が暗転を通らないゲームのための項目。全部の項目は書かなくてよい。書いていなければ前と同じに動く。座標は窓の中の座標。下の値は仮の値で、どのゲームの値でもない。値は取り込みで測って書く。

```json
{
 "tag": {"kind": "glyph", "box": [40, 500, 260, 530], "min_glyphs": 30, "read_name": true},
 "text": {"band": [60, 540, 1220, 700], "end_marks": "▼"},
 "choice": {"box": [300, 200, 980, 460], "rows_by_count": {"2": [[300, 250, 980, 300], [300, 330, 980, 380]]},
            "selected": "dark", "dark_margin": 12},
 "scene": {"box": [0, 0, 1280, 500], "text_diff": 20},
 "keys": {"advance": ["enter"], "cursor": ["up", "down", "lbutton"]},
 "input": {
  "text": {"keys": false, "actions": {
    "f9": {"do": "click", "at": [640, 600], "as": "advance"},
    "f10": {"do": "wheel", "at": [640, 400], "amount": 1}}},
  "choice": {"keys": false, "rows": "choice", "prev": "f11", "next": "f12", "pick": "f9"},
  "セーブ": {"keys": false, "rows": [[100, 120, 600, 200], [100, 220, 600, 300]],
            "prev": "f11", "next": "f12", "pick": "delete",
            "actions": {"backspace": {"do": "click", "at": [1200, 680], "button": "right"}}},
  "タイトル": {"keys": true}
 }
}
```

### 読む側の項目

- `tag.read_name`：札のある文で、札の字も読み、「名前。本文」と読む。`tag.box` が要る。同じ形の札は覚えて、読み直さない
- `text.end_marks`：文の終わりに出る「次へ」の印の字。読み手が返した文の終わりの1字だけを外す。同じ字が続くとき（「・・・」のような点の文）は外さない
- `choice.selected`：選ばれている行の見え方。`bright`（既定）は明るい行、`dark` は暗い行。`dark` のときは `dark_margin` が要る。ほかの行よりその差だけ暗い行が無ければ、前の行のままにする。選択肢が始まるたびに1行目に戻す
- `scene.text_diff`：暗転を通らない場面の切り替わりを見る。0（既定）は切。0より大きければ、文が出るたびに `scene.box` の粗い絵を前の文のときと比べ、差がこの値以上なら場面として説明する。始めて最初の文は場面とする。文でない画面を通っても、比べる絵は捨てない
- `keys.cursor` の `lbutton`：マウスの左ボタンも入力として見る。利用者が自分でマウスを押したあとの画面の変化を、利用者が動かしたものとして読む。`lbutton` は `keys` にだけ書ける。`input` の対応のキーには使えない

### 入力の対応（`input`）

本体がゲームへ入力を送るのは、利用者が対応表のキーを押した直後だけ。1回押して1つの動きだけ。本体が自分から文を進めたり、選んだりはしない。`input` が無いゲームでは何も送らない。送るのはマウスの動き（動かす、押す、ホイール）だけで、キーボードの入力は送らない。

本体はキーを読むだけで、ゲームにキーが届くのを止めない。だから対応に使うキーは、その画面でゲームが何もしないキーにする。押して画面が変わらないことを、取り込みで確かめる。ゲームが動くキーを使うと、ゲームと本体で2回動く。

- 鍵は画面の名前（`screens` の `name`）か種類（`text`、`choice`、`map`、`walk`、`menu`、`confirm`、`card`、`backlog`、`loading`）。名前が先に当たる。`text` は文の画面
- `keys`：その画面でゲームがキーで動くか（`true` か `false`）。記録のための項目で、本体の動きは変わらない。取り込みで試して書く
- `actions`：キーと動きの対応。鍵がキーの名前
  - `do`：`move`（マウスを動かす）、`click`（押す）、`wheel`（ホイールを回す）のどれか
  - `at`：動きの場所。窓の中の座標で、画面の中でないと読み込みで止まる
  - `button`：`click` のボタン。`left`（既定）か `right`
  - `amount`：`wheel` の回す量。上へ回すのが正、下へ回すのが負。`wheel` では0にできない
  - `as`：本体がその押しを何と見るか。`advance` なら文を進めたものとして、読み上げを止めてから送る。`cursor` ならカーソルを動かしたものとして、そのあとの画面の変化を読む。書かなければ、そのキーの元の役目（`keys.advance` のキーなら `advance`、それ以外は `cursor`）
- `rows`：行を選ぶ画面（選択肢、セーブやロードの枠、確認の窓のボタン）。`"choice"` と書けば `choice` の行を使う（`choice` の設定が要る）。箱の一覧なら、行の箱を上から順に書く
  - `prev`（既定 `up`）で前の行、`next`（既定 `down`）で次の行にマウスを乗せる。`pick`（既定 `enter`）で今の行を押す。3つは別のキーにし、`actions` のキーとも重ねない。既定のキーが本体に見えないゲームでは、見えるキーを書く（下の「対応表に使えるキー」。上の例は、そのために既定を使っていない）
  - その画面で最初の `prev` か `next` は、1行目に乗せる
  - 乗せるたびに、その行を読み上げる。選択肢は項目の字をすぐ読む。箱の行は、乗せてから0.35秒待って箱の中を読み手で読む。だから箱は、枠やボタンの字が全部入る大きさにする。字が無ければ「字がありません。」と言う。絵が完全に同じ箱は覚えて読み直さない。続けて動かしたら、読みかけの箱は読まない
  - 行を読み上げるまでは、`pick` を送らない。その画面に入ってから、本体が行を読み上げるまで、決めるキーを押しても何も送らず「行を選んでください。」と言う。読み上げに数えるのは、利用者が行のキーで乗せた行を本体が読んだときと、利用者が自分のマウスで選択肢の行を動かし、本体がその行を読んだとき。送らなかった決めるキーは、文を進めたことにも、選択肢を閉じたことにもしない
  - 選択肢でキーで乗せた行は、ゲームの光がその行に移るまで、画面の明るさで上書きしない

使えないキー：本体のキー（`f6` 読み直し、`f7` 絵の説明、`f8` 止める）、無変換（NVDA のキー）、マウスのボタン（`lbutton`、`rbutton`）、コントローラのボタン。キーの名前は `sotozuke/inputs.py` の `VK` にあるもの（`enter`、`space`、`escape`、`backspace`、`delete`、矢印の `up` `down` `left` `right`、`page_up`、`page_down`、`tab`、`f1`〜`f12`、`a`〜`z` など）。

### 対応表に使えるキー

対応表のキーは、本体を起動してそのキーを押したとき、本体の記録（`--log` に渡した置き場）に `"event": "key"` の行が、そのキーの名前（`source`）で出るかで確かめる。出ないキーは使わない。

#### NVDA のブラウズモード

Web の作りの窓（Chromium などで作ったゲームの窓）を NVDA がブラウズモードで開くと、字のキー、矢印、PageUp、PageDown を NVDA が受け取り、ゲームにも本体にも届かない。ゲームの窓で NVDA キー＋Space を押してフォーカスモードにすると届く。

- 取り込みの最初に、字のキーを1つ送って本体に見えるかを確かめる。見えなければフォーカスモードにしてから調べる
- 本体は、NVDA が動いていてゲームの窓が Web の作りなら、始めに1回「NVDA のブラウズモードでは、字や矢印のキーがゲームに届きません。」と案内する。記録の `nvda_check` に、NVDA が動いていたか（`running`）、窓が Web の作りか（`web`）、窓の種類の名前（`classes`）が出る
- 本体からは、NVDA が今ブラウズモードかどうかは分からない（NVDA に聞く口が無い）。なので案内は窓の作りで出す。フォーカスモードにしたあとも、始めの案内は出る
- 利用者もフォーカスモードにして遊ぶ。ブラウズモードのままだと、利用者の字や矢印のキーもゲームに届かない

11-07 に、1本目のゲームの窓（Web の作り）で、`ingest.gamectl` から送ったキーが本体と同じ見回りに見えるかを、モードを切り替えて確かめた。

| キー | ブラウズモード | フォーカスモード |
|---|---|---|
| 字（n、a） | 見えない | 見える |
| 矢印（上、下） | 見えない | 見える |
| PageUp、PageDown | 見えない | 見える |
| Esc | 見えない | 見えない |
| F9、Delete、Backspace | 見える | 見える |

- 11-06 に1本目と2本目で「本体に見えないキー」と書いたもの（字、矢印、Esc、PageUp、PageDown）は、Esc を除いて、NVDA のブラウズモードが原因だった
- Esc は、1本目ではどちらのモードでも見えなかった。3本目の取り込みでは、ブラウズモードでも見えた（Enter、Space、Esc、F キー、Delete、Backspace が素通りした）。1本目で Esc が見えない理由は分かっていない
- Web の作りでない窓では、NVDA はふつうブラウズモードにしない。基準のゲームの窓の作りは確かめていない

#### キーの選び方

見えるキーでも、ゲームが何かするキーは使わない。キーが効くのに、選ばれている所が画面に出ないゲームがある（見えない選択）。そのゲームでは Enter や Space が見えない選択を押してしまうので、上下と Enter と Space は対応表に使わない。候補のキーは、その画面で選べる物（枠など）に乗せた状態でも押して確かめる。乗せると動くキーがある。

迷ったら、どちらのモードでも見えたキー（F9〜F12、Delete、Backspace）から選ぶ。F6〜F8 は本体のキーなので使えない。F11 で全画面になるゲームがあるので、F11 も押して確かめる。
