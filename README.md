# 外付けの目（sotozuke-no-me）

Built with Claude: Japan 2026（2026年11月2日〜11月10日）の作品。

全盲の人が、市販のノベルゲームを自分の手で遊ぶための道具。ゲームの画面を見て、声のない文、選択肢、メニュー、場面の絵を、声で伝える。操作は利用者のキーボードかコントローラ。作者の守井は全盲の工学博士で、この道具のいちばん最初の利用者でもある。

## なぜ作ったか

1. 目の見えない人は、遊べるゲームを自分たちで作ってきた。音だけで遊ぶ「オーディオゲーム」で、英語圏の [AudioGames.net](https://audiogames.net/) や、日本の [視覚障害者向けアクセシブルゲーム情報まとめWiki](https://www.mm-galabo.com/AcGameWiki/) に集まっている。作り手は日本で3〜4人、英語圏で数十人ほど（[4Gamer、2018年](https://www.4gamer.net/games/999/G999901/20181002079/)）
2. 市販のゲームで、全盲の人が遊べるものはごく一部。2022年の記事は、視覚をまったく使わずに完全に遊べる作品を「今のところ『The Last of Us Part II』くらい」と書いた（[電ファミニコゲーマー](https://news.denfaminicogamer.jp/kikakuthetower/220728d)）。画面読み上げに対応した市販のノベルゲームは、調べた範囲では見つからなかった
3. 日本で視覚障害の身体障害者手帳を持つ人は、在宅で約27万3千人、約450人に1人（2022年、[厚生労働省](https://www.mhlw.go.jp/toukei/list/seikatsu_chousa_b_r04.html)）。世界で失明している人は、約4330万人と推計されている（2020年、[Lancet Global Health](https://pubmed.ncbi.nlm.nih.gov/33275950/)）

ノベルゲームは、字を読んで進めるゲームなので、字と絵が声になれば遊べる。外付けの目は、ゲームにもゲーム会社にも手を入れずに、画面の外から字と絵を声にする。

## 何ができるか

- 声のない文を、字が出たらすぐ読む。声のある台詞には読み上げをかぶせない
- 選択肢を全部読み、カーソルを動かすたびに、その項目をすぐ読む
- 場面が変わったら、絵の説明を聞ける
- タイトル、メニュー、セーブ、ロード、確認の窓を読む
- 行き先の地図を言葉にする
- 3Dの歩く画面で、地図で選んだ人が何度右か左か、どれくらい近いかを言う。向きを変えている間は角度の音、壁に当たると低い音で知らせる。人の近くに出る「話す」の案内の字も読む
- 次へ進むキーを押すと、今の読み上げはすぐ止まり、次の文を読む
- キーで動かずマウスが要るゲームでは、利用者のキーをマウスの動きに言い換えて送る。行を選ぶ画面（選択肢、セーブやロードの枠、確認の窓のボタン）では、上下のキーでマウスを次の行に乗せ、乗せるたびにその行を読む
- 名前の札があれば、「名前。本文」と読む

## 仕組み

1. 画面を10コマ毎秒で撮る
2. 手元の計算で、字が止まったか、画面の種類が変わったか、場面が明けたかを見る。API は呼ばない
3. 読むと決めたときだけ Claude を呼ぶ。本文は Claude Haiku 5.5 が、そのままと3倍に拡大した画面の2通りで同時に読み、答えが割れた文だけ Claude Sonnet 5.5 が決める。場面の絵と行き先の地図は Sonnet が言葉にする
4. Windows の声で読む。一度作った声は取っておく

読むのはいつも最新の1つだけで、順番待ちの列は作らない。利用者が先へ進んだら、作りかけの結果は捨てる。

ゲームごとの違い（字の出る範囲、画面の種類の見分け方、キーとマウスの対応）は、すべてゲームの設定のファイル（`games/<ゲーム>.json`）に書く。本体のコードには、どのゲームの座標も値も入っていない。書き方は `games/README.md` にある。

## 取り込み

新しいゲームの設定のファイルを作ることを、ここでは「取り込み」と呼ぶ。取り込みは、Claude Code のスキル `add-game`（`.claude/skills/add-game/SKILL.md`）で行う。Claude Code が画面と音だけでゲームを調べ、設定のファイルを作り、最後に本体をキーだけで動かして物語の始めから終わりまで通して確かめる。

1本取り込むごとに、つまずいた所をスキルの「経験」の節に足す。本体を直さないと届かない所が見つかったときは、どのゲームにも効く形で本体を直し、別の新しいセッションで測り直す。

## Claude の使い方

- 遊ぶとき：本体が Claude Haiku 5.5 と Claude Sonnet 5.5 を呼ぶ（上の「仕組み」）。取り込みの間に本体が使った API の費用は、2本目で0.20ドル、3本目で0.085ドル、3本目の測り直しで約0.10ドルだった
- 取り込むとき：Claude Code のスキル `add-game` を使う。測るときは、そのゲームについて何も知らない新しいセッションに任せた。そのセッションの指示書で、ゲームのファイル、セーブ、台本、Web の検索、過去の記録を読むことを禁じた。人は質問に答えない
- 本体を直すとき：直すセッションと測るセッションを分けた。直すセッションは、測るゲームを起動しない。測ったセッションの記録からは、ゲームの座標、値、題名、物語を除いた引き継ぎの文書だけを読む。直したあと、別の新しいセッションで測り直した
- 作り方：コードを書く前に設計を書き、フェイズに分け、フェイズごとにコマンドで確かめられる合格の条件を置いた。合格の条件は作る前に決め、あとから緩めない（[`decisions.md`](decisions.md) の「関門の数字」）。条件を通るまで次へ進まず、フェイズが終わるたびに、それまでの全部のテストを流した。テストは440件ある

### 妻のゲーム3本

他人が作った無料の日本語のノベルで、公開してよいことまで権利が文書で確かめられるものは、調べた範囲で見つからなかった。そこで、チームのもう1人である妻（みお）に作ってもらった。

妻に頼んだのは次のこと。

- 2026年11月2日 12:30 から、ゼロから作る
- この道具に合わせず、普通のゲームとして作る
- 題名、物語、絵、選択肢の数を、守井にも、守井の側の Claude にも話さない

守井と守井の側の Claude は、遊べる形のゲームだけを受け取り、ゲームのファイルの中は開いていない。

妻のゲームの作り方。妻が筋と指示を決め、妻の側の Claude Code がコードと台本を書き、台本に妻が手を入れた。絵は ChatGPT の画像生成、BGM は Gemini（Lyria）、声は Gemini TTS で作った。3本目の人物は VRoid のサンプル。素材ごとの出どころと条件は、各ゲームのリポジトリの README にある。

結果。目標は13（タイトル、はじめから、本文、名前の札、声の有無、次へ、選択肢、場面の切り替わり、場面の説明、セーブ、ロード、タイトルからロード、キーだけで最後まで遊ぶ）。どれも、人が答えた回数は0。

- 1本目の初回：12の目標（このときは「キーだけで最後まで遊ぶ」が無かった）のうち11に、35分23秒で届いた。メニューと選択肢がキーで動かず、マウスが要るゲームだった。そこで、利用者のキーをマウスの動きに言い換える決まりを本体に入れた
- 1本目の取り込み直し：13の目標に、60分20秒で全部届いた。キーだけで物語の最後まで通し、読み落としは0
- 2本目：13の目標に、54分24秒で全部届いた。本体のコードを1行も変えずに、キーだけで物語の最後まで遊べた。声のない地の文49文の読み落としは0
- 3本目：13の目標に54分07秒で届いたが、3Dの歩く画面は本体の道案内がたびたび外れ、目の見えない人が歩いて人に会えるところまで届かなかった。足りない所を、どのゲームにも効く形で本体に入れた

取り込みの時間は、1本ごとに縮んではいない。増えたのは、届いた目標の数と、本体を変えずに遊べるゲームの数。

最後の版の本体で4本をもう一度、前と同じ区間で通した。4本とも、読み落としは増えていない。妻の1本目では、字の読み違いが1文から3文に増えた。

## できていないこと

- 3本目の歩く画面は、最後の場所へ本体の声だけで行けることを確かめていない
- ゲームの設定は、画面の大きさに結びついている。画面の大きさが変わると、本体はそのゲームを読まない（間違えて読まないように、大きさが違う画面は断る）。設定を作り直す必要がある
- NVDA のブラウズモードでは、字と矢印のキーがゲームにも本体にも届かない。本体は始まるときにそれを知らせる。ただし妻の1本目は、フォーカスモードにするとタイトルから進めなかった。このゲームはブラウズモードのまま遊ぶ
- 声のある台詞は、ゲームの声に任せて読まない。声のある文かどうかは、名前の札などで見分ける

## これから

1. まず守井が、とことん遊ぶ。市販のノベルゲームには、遊びたかったのにあきらめていた作品が多い。この道具で取り込み、次々に試す
2. 自分の手でゲームを遊びたい視覚障害者は、世界中にいるはず。ハッカソンで受け取った API のクレジットで、守井が試しのサーバーを用意し、それぞれが遊びたいゲームをスキル `add-game` で取り込めるようにしたい。規約、費用、画面の画像の扱いは、これから確かめる
3. 画面の字と絵を声にする仕組みは、少し広げれば、ほかのゲームやアニメにも使える見込みがある。日本のアニメやゲームは世界で楽しまれているが、目の見えない人に届く作品はまだ少ない。守井1人では時間も考えも足りないので、関心のある世界中の人と一緒に育てたい

## 使い方

Windows 11 と Python 3.12 で動かしている。

```
uv venv --python 3.12 .venv
uv pip install --python .venv -e .[dev]
```

API の鍵のファイルのパスを環境変数 `ANTHROPIC_API_KEY_FILE` に入れる。

```
python -m sotozuke --game games/ゲーム.json
```

初期設定：ゲームの文字表示速度を、いちばん速くしておく。遊ぶ間は Windows の通知を切る（集中モードなど）。通知が本文の上に重なると、新しい文と見て読み始めることがある。

既定のキー：F6 で読み直す、F7 で絵の説明を聞く、F8 で読み上げを止める。文の無い画面で F6 を押すと、画面全体の字を読む。コントローラは左スティックの押し込みが読み直し、右スティックの押し込みが説明。

API の費用の上限は、既定で4.5ドル。届くと本体が止まる。変えるときは `--budget` で渡す。

声は Windows 標準の Haruka が既定。ほかの声は `--voice-command` でつなげる。彩（Irodori-TTS）を使う場合は、彩の手順で別に用意する。リポジトリには入っていない。

### 妻のゲームで試す

検証に使った妻のゲーム3本の設定は、`games/wife-game1/`〜`games/wife-game3/` に入っている。ゲームは、各リポジトリの Release v1.0 から手に入る（1本目 https://github.com/fwaohaoi1g168/game1/releases/tag/v1.0 、2本目 https://github.com/fwaohaoi1g168/game2/releases/tag/v1.0 、3本目 https://github.com/fwaohaoi1g168/game3/releases/tag/v1.0 ）。

1. 画面の大きさを合わせる。設定は、検証したときの画面の大きさで作ってある。1本目は 1024×768 の画面（ゲームの窓は 1008×681）、2本目と3本目は 1360×768 の画面（窓は 800×450 と 1280×681）。大きさが違うと、本体はゲームを読まない。そのときは、スキル `add-game` で取り込み直す
2. ゲームを起動し、タイトルの画面にしておく
3. 本体を起動する

```
python -m sotozuke --game games/wife-game2/wife-game2.json
```

4. ゲームのキーで遊ぶ。F6 で読み直し、F7 で絵の説明、F8 で読み上げを止める
5. NVDA を使っていて、字や矢印のキーが届かないときは、NVDA キーと Space でフォーカスモードにする。1本目はブラウズモードのまま遊ぶ（上の「できていないこと」）

設定の中の `tpl/` の画像は、画面の種類を見分けるために、妻のゲームの画面から切り出した小さな画像。権利は妻のゲームと同じで、MIT ライセンスの対象外。
