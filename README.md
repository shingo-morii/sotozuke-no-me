# 外付けの目（sotozuke-no-me）

Built with Claude: Japan 2026（2026年11月2日〜11月10日）の作品。

全盲の人が、市販のノベルゲームを自分の手で遊ぶための道具。ゲームの画面を見て、声のない文、選択肢、メニュー、場面の絵を、声で伝える。操作は利用者のキーボードかコントローラ。作者の守井は全盲の工学博士で、この道具のいちばん最初の利用者でもある。

## 何ができるか

- 声のない文を、字が出たらすぐ読む。声のある台詞には読み上げをかぶせない
- 選択肢を全部読み、カーソルを動かすたびに、その項目をすぐ読む
- 場面が変わったら、絵の説明を聞ける
- タイトル、メニュー、セーブ、ロード、確認の窓を読む
- 行き先の地図を言葉にする
- 3Dの歩く画面で、地図で選んだ人が何度右か左か、どれくらい近いかを言う。向きを変えている間は角度の音、壁に当たると低い音で知らせる
- 次へ進むキーを押すと、今の読み上げはすぐ止まり、次の文を読む
- キーで動かずマウスが要るゲームでは、利用者のキーをマウスの動きに言い換えて送る。行を選ぶ画面（選択肢、セーブやロードの枠、確認の窓のボタン）では、上下のキーでマウスを次の行に乗せ、乗せるたびにその行を読む
- 声の無いゲームで名前の札があれば、「名前。本文」と読む

## 仕組み

1. 画面を10コマ毎秒で撮る
2. 手元の計算で、字が止まったか、画面の種類が変わったか、場面が明けたかを見る。API は呼ばない
3. 読むと決めたときだけ Claude を呼ぶ。本文は Claude Haiku 5.5 が、そのままと3倍に拡大した画面の2通りで同時に読み、答えが割れた文だけ Claude Sonnet 5.5 が決める。場面の絵と行き先の地図は Sonnet が言葉にする
4. Windows の声で読む。一度作った声は取っておく

読むのはいつも最新の1つだけで、順番待ちの列は作らない。利用者が先へ進んだら、作りかけの結果は捨てる。

実際の市販のゲームで通しの試験をして、声の無い文47文を、読み落とし0、字の間違い0で読んだ。キーを押してから読み上げが止まるまでは最大13ミリ秒だった。

## 取り込み

新しいゲームは、Claude Code のスキル `add-game`（`.claude/skills/add-game/SKILL.md`）で取り込む。Claude Code が画面と音だけでゲームを調べて、`games/<ゲーム>.json` を作る。1本取り込むごとに、スキルの経験の節に分かったことを足すので、次のゲームは速くなる。本体のコードは変えない。

## 入力を送る範囲

遊ぶときの本体（`sotozuke`）がゲームへ入力を送るのは、利用者がゲームの設定の対応表（`input`）にあるキーを押した直後だけ。1回押して1つの動きだけで、送るのはマウスの移動、押し、ホイールのどれか。キーボードの入力は送らない。本体が自分から文を進めたり、選んだりしない。対応表が空のゲームでは何も送らない。

キーで動かないゲームでも、全盲の人が自分の手で操作できるようにするための決まり（2026-11-06 に守井が改めた。前は「本体はゲームにキーを送らない」）。

送る処理は `sotozuke/sender.py` の1か所にまとめてある。そこを呼ぶのは判断の中心が利用者のキーを受けたときだけで、そのことと、対応表が空なら何も送らないことは、テストで機械で確かめている。本体はキーを読むだけで、ゲームにキーが届くのは止めない。なので、対応表に書くのは、その画面でゲームが何もしないキーにする。それを確かめるのは取り込みの仕事。

探索の道具（`ingest`）と、手元の通しの試験の道具は、調べるためにキーとマウスを送る。

## 使い方

Windows 11 と Python 3.12 で動かしている。

```
uv venv --python 3.12 .venv
uv pip install --python .venv -e .[dev]
```

API の鍵のファイルのパスを環境変数 `ANTHROPIC_API_KEY_FILE` に入れる。

```
python -m sotozuke --game games/ゲーム.json
```

初期設定：ゲームの文字表示速度を、いちばん速くしておく。遊ぶ間は Windows の通知を切る（集中モードなど）。通知が本文の上に重なると、新しい文と見て読み始めることがある。

既定のキー：F6 で読み直す、F7 で絵の説明を聞く、F8 で読み上げを止める。文の無い画面で F6 を押すと、画面全体の字を読む。コントローラは左スティックの押し込みが読み直し、右スティックの押し込みが説明。

声は Windows 標準の Haruka が既定。ほかの声は `--voice-command` でつなげる。彩（Irodori-TTS）を使う場合は、彩の手順で別に用意する。リポジトリには入っていない。
